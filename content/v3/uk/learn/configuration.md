# Конфігурація

## Огляд

Flight надає простий спосіб налаштувати різні аспекти фреймворку відповідно до потреб вашого застосунку. Деякі налаштування встановлені за замовчуванням, але ви можете перевизначити їх за потреби. Ви також можете встановити власні змінні для використання в усьому вашому застосунку.

## Розуміння

Ви можете налаштувати певну поведінку Flight, встановлюючи значення конфігурації
через метод `set`.

```php
Flight::set('flight.log_errors', true);
```

У файлі `app/config/config.php` ви можете побачити всі доступні змінні конфігурації за замовчуванням.

## Основне використання

### Опції конфігурації Flight

Нижче наведено список усіх доступних налаштувань конфігурації:

- **flight.base_url** `?string` - Перевизначає базову URL-адресу запиту, якщо Flight працює у підкаталозі. (за замовчуванням: null)
- **flight.case_sensitive** `bool` - Чутливе до регістру зіставлення URL-адрес. (за замовчуванням: false)
- **flight.handle_errors** `bool` - Дозволяє Flight обробляти всі помилки внутрішньо. (за замовчуванням: true)
  - Якщо ви хочете, щоб Flight обробляв помилки замість стандартної поведінки PHP, це має бути true.
  - Якщо у вас встановлено [Tracy](/awesome-plugins/tracy), вам потрібно встановити це значення false, щоб Tracy могла обробляти помилки.
  - Якщо у вас встановлено плагін [APM](/awesome-plugins/apm), вам потрібно встановити це значення true, щоб APM міг реєструвати помилки.
- **flight.log_errors** `bool` - Реєструвати помилки у файл журналу помилок веб-сервера. (за замовчуванням: false)
  - Якщо у вас встановлено [Tracy](/awesome-plugins/tracy), Tracy реєструватиме помилки на основі конфігурацій Tracy, а не цієї конфігурації.
- **flight.debug** `bool` - Виводити детальну інформацію про помилку (повідомлення винятку, код і трасування стека) у браузері під час виникнення помилки. (за замовчуванням: false)
  - **Ніколи не вмикайте це у продакшені** — це розкриває внутрішні деталі застосунку. Використовуйте лише для локальної розробки або стейджингу.
  - Коли `false`, замість цього показується загальне `500 Internal Server Error`. Поєднуйте з `flight.log_errors` для фіксації помилок на стороні сервера.
- **flight.allow_method_override** `bool` - Дозволити перевизначення HTTP-методу через заголовок запиту `X-HTTP-Method-Override` або поле `_method` у тілі POST-запиту. (за замовчуванням: true)
  - **Рекомендовано встановити значення `false`** для застосунків, яким не потрібне спуфінг методів на основі HTML-форм, оскільки це запобігає підробці клієнтами запитів `DELETE` або `PUT` через стандартну форму POST.
  - Див. [Безпека](/learn/security#flight-configuration-hardening) для отримання додаткової інформації.
- **flight.views.path** `string` - Каталог, що містить файли шаблонів перегляду. (за замовчуванням: ./views)
- **flight.views.extension** `string` - Розширення файлу шаблону перегляду. (за замовчуванням: .php)
- **flight.content_length** `bool` - Встановити заголовок `Content-Length`. (за замовчуванням: true)
  - Якщо ви використовуєте [Tracy](/awesome-plugins/tracy), це потрібно встановити false, щоб Tracy могла правильно відображатися.
- **flight.v2.output_buffering** `bool` - Використовувати застаріле буферування виводу. Див. [міграцію на v3](migrating-to-v3). (за замовчуванням: false)

### Конфігурація завантажувача

Існує додаткова конфігурація для завантажувача. Це дозволить вам
автозавантажувати класи з `_` у назві класу.

```php
// Увімкнути завантаження класів з підкресленнями
// За замовчуванням true
Loader::$v2ClassLoading = false;
```

### Змінні

Flight дозволяє зберігати змінні, щоб їх можна було використовувати будь-де у вашому застосунку.

```php
// Збережіть вашу змінну
Flight::set('id', 123);

// В іншому місці вашого застосунку
$id = Flight::get('id');
```
Щоб перевірити, чи встановлено змінну, ви можете зробити:

```php
if (Flight::has('id')) {
  // Зробити щось
}
```

Ви можете очистити змінну, виконавши:

```php
// Очищає змінну id
Flight::clear('id');

// Очищає всі змінні
Flight::clear();
```

> **Примітка:** Просто тому, що ви можете встановити змінну, не означає, що ви повинні це робити. Використовуйте цю функцію помірно. Причина полягає в тому, що все, що зберігається тут, стає глобальною змінною. Глобальні змінні погані, тому що їх можна змінити з будь-якого місця у вашому застосунку, що ускладнює пошук помилок. Крім того, це може ускладнити такі речі, як [модульне тестування](/guides/unit-testing).

### Помилки та винятки

Усі помилки та винятки перехоплюються Flight і передаються методу `error`,
якщо `flight.handle_errors` встановлено true.

Стандартна поведінка полягає в надсиланні загальної відповіді `HTTP 500 Internal Server Error`
з деякою інформацією про помилку.

Ви можете [перевизначити](/learn/extending) цю поведінку для власних потреб:

```php
Flight::map('error', function (Throwable $error) {
  // Обробити помилку
  echo $error->getTraceAsString();
});
```

За замовчуванням помилки не реєструються на веб-сервері. Ви можете увімкнути це, змінивши конфігурацію:

```php
Flight::set('flight.log_errors', true);
```

#### 404 Не знайдено

Коли URL-адресу не вдається знайти, Flight викликає метод `notFound`. Стандартна
поведінка полягає в надсиланні відповіді `HTTP 404 Not Found` з простим повідомленням.

Ви можете [перевизначити](/learn/extending) цю поведінку для власних потреб:

```php
Flight::map('notFound', function () {
  // Обробити не знайдено
});
```
